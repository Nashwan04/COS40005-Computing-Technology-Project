## Questions the client/professor may ask, with precise answers

**Q: What's the purpose of JSON input to JSON output?**

A: The transformation is *structural and semantic*: flat/nested records become a typed graph represented as unique nodes, labeled directed edges, and adjacency indexes. JSON is one serialization option; GraphML and node/edge CSV are also exported. We can query neighbours by relationship type.

**Q: Why is this heterogeneous?**

A: There are multiple node types (Yelp: Review/User/Business; DBLP: Paper/Author/Venue) and multiple typed links (AUTHORED_BY, ABOUT, PUBLISHED_IN, and where available CITES).

**Q: How does the algorithm prevent duplicates?**

A: Each node key is formed from `Type:original_ID`. A Python dictionary ensures the same typed entity is inserted once. Edges can point to that shared key; identical source–target–relation triples are deduplicated.

**Q: What actually creates the edge?**

A: The external schema names an explicit source reference field; e.g., `review.business_id` resolves to `Business.business_id`. The edge stores the source record ID and reference field/value as evidence. For DBLP, `authors[].id` and `venue.id` are normalized first.

**Q: How do you distinguish a node and an attribute?**

A: The schema deliberately models identity-bearing entities (Business, User, Review) as nodes, but descriptive scalars such as review stars, dates and paper year as attributes. This is a modeling choice that should reflect the intended questions.

**Q: What if the raw DBLP data has no IDs?**

A: We do not silently infer that two matching author names are the same person. The normalizer records missing-ID warnings and skips unsupported links unless rules are explicitly approved.

**Q: What if a citation points to a paper not sampled?**

A: We build an induced sample graph: retain citations only when both papers are present in the selected source sample; report how many were excluded.

**Q: How do you validate the edges?**

A: Structural checks ensure all nodes/edges use declared types and endpoints exist. The independent tool checks every stored edge's source ID, reference field, destination ID and relation against the original source record.

**Q: Have you completed arbitrary-format conversion and schema discovery?**

A: No. This version is a defensible JSON/JSONL schema-driven proof of concept. XML, RDF, automatic schema inference and CSR require additional work and should be listed as limitations or future enhancements.
